# 数字孪生企业级重构 + 16 模块落地蓝图

## Context（为什么做）

`README.md` 第 647-663 行新增的 16 个功能模块（流程图/甘特图/看板/调度视图/透视分析/PDF模板/协同富文本/文档模板/邮件模板/地图GIS/ETL管道/API编排/IoT监控/Office编辑/白板/知识图谱/数字孪生）经扫描**全部为企业级"过家家"实现**：

- **数字孪生（最严重）**：用 Canvas 2D + 等距投影模拟 3D，仅 cube/cylinder/plane/sphere 4 种几何体；无 WebGL、无模型导入、无 PBR 材质/光照/阴影、数据仅 `Math.random`、无模型部件↔点位绑定、无告警视觉联动、无时间轴回放、无巡检路径、无实例化/LOD、无标注测量、无场景保存、无截图录屏、无多人协同。
- **其余 15 模块**：均仅前端模拟，缺真实后端接入、协议直连、协同权限、导出集成。ETL 不真执行、API 编排不真调用、IoT 不接 MQTT、地图不用 Leaflet/Mapbox、Office 不真编辑、富文本不真协同。
- 用户原话："企业级的数字孪生是这样的？一个数字孪生的设计器会这么简单？请站在企业级可落地的视角进行重新优化"。

**本轮目标**：
1. 把**数字孪生**做成企业级标杆（真 3D 引擎 + 工业模型 + 协议适配 + 回放/巡检/告警联动/协同预留）。
2. 其余 15 模块给出**目标架构蓝图 + 分阶段路线图**，本轮不实施，下一轮按优先级推进。
3. 重写 `README.md` 647-663 行，从"功能名清单"升级为"企业级能力矩阵 + 架构 + 落地路径"。

**关键决策**（已基于用户表态默认确定）：
- 范围：数字孪生先行 + 全模块蓝图（16 模块同步重构工作量 5 万+ 行不现实）
- 引擎：引入 Three.js（企业级 WebGL 事实标准，非 jQuery 类，不违反项目硬约束）
- 协议：前端适配层 + Mock + 预留真实接入（本轮独立交付，不依赖后端改造）

### 1.3 核心类 API 签名（关键）

**DtEngine**（引擎主类，所有子系统的统一入口）：
```typescript
class DtEngine {
  constructor(opts: DtEngineOptions): void;
  init(): Promise<void>;          // 初始化所有子系统并启动渲染循环
  renderOnce(): void;             // on-demand 模式由外部触发
  pause(): void; resume(): void;
  dispose(): void;                // 释放所有 Three.js 资源
  resize(w: number, h: number): void;
  onBeforeRender(cb: (delta: number) => void): () => void;
  onAfterRender(cb: (delta: number) => void): () => void;
  // 只读子模块：renderer, sceneManager, modelLoader, materialLibrary,
  //             lightingRig, cameraRig, picker, animator, performance, exporter
}
```

**IDataAdapter**（协议适配接口，所有适配器统一契约）：
```typescript
interface IDataAdapter {
  readonly id: string;
  readonly type: "mock" | "mqtt" | "opcua" | "websocket";
  readonly status: "disconnected" | "connecting" | "connected" | "error";
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  subscribe(pointIds: string[]): void;
  unsubscribe(pointIds: string[]): void;
  onMessage(cb: (point: DtDataPoint) => void): () => void;
  onStatusChange(cb: (status) => void): () => void;
  publish(pointId: string, value: unknown): Promise<void>;
  dispose(): void;
}
```

**DtDataBinder**（rAF 合批是性能关键）：
```typescript
class DtDataBinder {
  bind(b: DtDataBinding): void;
  ingest(point: DtDataPoint): void;  // 内部 rAF 合批后 flush 到 SceneManager/MaterialLibrary
  replay(point: DtDataPoint): void;  // 时间轴回放注入
  serialize(): DtDataBinding[];
}
```

**DtAlertAction**（告警视觉联动）：
```typescript
type DtAlertActionType = "highlight" | "animate" | "popup" | "sound" | "webhook" | "log";
interface DtAlertAction {
  type: DtAlertActionType;
  nodePath?: string;       // highlight/animate 目标
  color?: string;          // 高亮颜色
  animationName?: string;  // 动画 clip
  popupTitleKey?: string;  // 弹窗 i18n key
  url?: string;            // webhook
}
```

完整类型清单（30+ 接口）见 `types.ts` 重写：`DtEngineOptions`、`DtSceneAsset`、`DtModelNode`、`DtDataPoint`、`DtDataBinding`、`DtAlertRule`、`DtAlertEvent`、`DtTimelineState`、`DtInspectionPath`、`DtAnnotation`、`DtMeasurement`、`DtMaterialDescriptor`、`DtLightDescriptor`、`DtCameraState`、`DtPickResult`、`DtPerformanceStats`、`DtPersistedScene`（场景保存格式 v2.0）等。

### 1.4 数据流（核心调用链）

```
DataAdapter (Mock/MQTT/WS/OPC-UA)
   │ onMessage(DtDataPoint)
   ▼
DtDataBinder ── path→node 映射 ──► DtSceneManager.updateNodeTransform
   │                                    │
   ├─► DtAlertEngine.evaluate(point)    ├─► DtAnimator.applyState()
   │       │                            │
   │       ├─► 视觉联动（高亮/动画/弹窗） │
   │       └─► emit AlertEvent           │
   ▼                                        ▼
DtTimelinePlayer.buffer(point)         DtEngine.renderLoop(rAF)
   │                                        │
   ▼                                        ▼
历史回放 → DataBinder.replay(point@t)   WebGLRenderer.render(scene, camera)
```

### 1.5 DtSceneViewport.vue（替换 DtSceneCanvas.vue 的核心面板）

**职责**：作为 Three.js renderer 的宿主，将引擎渲染与 Vue 响应式系统对接。

**关键技术点**：
- `canvasRef: shallowRef<HTMLCanvasElement | null>` + `containerRef: shallowRef<HTMLDivElement | null>`（精确类型，遵循项目约定）
- `onMounted` 调用 `useDtEngine().init(canvas, container)` → `provide(DtEngineKey, engineRef)`
- `ResizeObserver` 监听容器尺寸变化 → `engine.resize(w, h)`（内部 `renderer.setSize` + `camera.aspect` 更新）
- 鼠标事件在 `containerRef` 监听，按模式转发：`view`→OrbitControls、`edit`→Gizmo+Picker、`measure`→Measurement、`annotation`→Annotation
- 屏幕坐标→NDC：`((x / width) * 2 - 1, -(y / height) * 2 + 1)`
- 鼠标事件用 `requestAnimationFrame` 节流（项目约定）
- DPR：`Math.min(window.devicePixelRatio, maxPixelRatio ?? 2)`
- 监听 `webglcontextlost` / `webglcontextrestored` 做降级恢复
- Canvas 必须 `display: block`，容器 `position: relative`，HUD 浮层 `position: absolute`

## 三、其他 15 模块企业级蓝图（下一轮，本轮仅规划）

每个模块的当前差距、目标架构、推荐技术栈、关键能力补齐清单如下：

### 3.1 ETL 管道（重差距）
- **当前**：仅前端节点配置 + 拓扑排序模拟执行，无真实数据流转
- **目标架构**：前端 `EtlDesigner`（节点编辑/属性/预览）+ 后端 `EtlExecutor`（真实执行引擎）+ WebSocket 实时日志/进度

## 六、风险与权衡

| 风险 | 应对 |
|---|---|
| Three.js 包体积（~600KB gzip） | `external` 库模式不打包；按需 `import` + Tree-shaking；Loader 用 dynamic import 懒加载；实测核心+GLTFLoader 约 350KB gzip |
| 模型文件 5-50MB | 生产走 OSS/CDN（`assetBase` 指向）；开发用小测试模型；Draco+Meshopt 压缩至 1/5；`preload()` 进度条 |
| WebGL2 兼容性 | 初始化检测 `getContext("webgl2")` 失败降级 WebGL1；无 WebGL 显示降级提示并保留旧 Canvas 2D 兜底；目标浏览器 Chrome 90+/Edge 90+/Firefox 88+/Safari 15+ |
| 性能底线 | 小型 50K 面 60FPS / 中型 500K 面 60FPS / 大型 2M 面 30FPS / 超大 5M 面 30FPS；实例化+LOD+视锥剔除+`on-demand` 渲染+自动降级 |
| 内存泄漏 | `removeNode` 递归 `dispose` geometry/material/texture；`DtEngine.dispose` 统一释放 + `forceContextLoss`；开发模式监控 `performance.memory` |
| 协议直连安全 | MQTT/OPC-UA 默认 `useGatewayProxy: true` 走后端网关；password 不写入场景 JSON，运行时注入 |
| 多人协同冲突 | `useDtCollab` 第一版只同步光标/选中/视角（read-only 协同）；写操作乐观锁+版本号；完整 OT/CRDT 不在本次范围 |

# 2026-06-03

## 修复 parseDateByType 日期解析函数

- **文件**: `src/api/date_utils.ts`
- **问题**: parseDateByType 存在多个 bug，导致不同类型日期数据无法正确格式化
- **修复内容**:
  1. subType 参数被忽略 → 新增 effectiveType 逻辑，subType 优先于 type
  2. range 递归调用参数顺序错误 → 修正为 (val, type, baseType, needSecond, split)
  3. time/time-picker 类型未处理 → 新增 formatTimeValue 函数，不走 new Date()
  4. months/dates/years 数组直接 return val → 新增数组遍历按子类型格式化
  5. month 值为纯数字 "06" 时 new Date("06") 无效 → 正则检测直接返回
  6. fieldMonths JSON 字符串数组未解析 → 新增 JSON.parse 递归处理
  7. 已格式化日期字符串（"2026-12-13"、"2026/12/13"）走 new Date() 有时区偏移风险 → 新增 tryAlreadyFormatted 正则识别
  8. time-picker 可能为范围 → 新增 timerange 到 dateTypes，formatTimeValue 支持数组/分隔符格式范围
  9. dateTypes 数组新增 time、time-picker、timerange
  10. **ISO 字符串时区偏移根因修复**：新增 `extractISODateParts` + `formatDateByPatternUTC` + `isDateOnlyType`，对 date-only 类型（year/month/date/week 及其 range/多选变体）从 ISO 字符串直接提取 UTC 日期部分，避免 `new Date()` 本地时区偏移（如 "2026-09-30T16:00:00.000Z" 在 UTC+8 下被错误解析为 10 月）
  11. months 数组含 ISO 字符串时改用递归调用 `parseDateByType(v, type, "month", ...)` 而非直接返回
- **调用方式**: `StarHorseTableColumn.vue` 第 140 行 `parseDateByType(val, item.type, item.preps?.type)`

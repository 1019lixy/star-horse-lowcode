# 2026-06-04

## 修复 week 类型显示为日期而非周数

- **文件**: `src/api/date_utils.ts` — `tryAlreadyFormatted` 函数
- **问题**: week 类型 ISO 字符串被 `tryAlreadyFormatted` 拦截后返回日期字符串 `"2026-06-08"`，没走周数格式化
- **修复**: week case 改为从 ISO/已格式化日期直接计算周数，返回 `"2026第23周"` 格式

## 修复 time/time-picker 组件被错误路由为 datetime-item

- **文件**: `src/api/system.ts`、`time-picker-item.vue`
- **问题**: `dateType` 新增 time/time-picker/timerange 后，`dateCompList()` 也包含了这些类型，导致 `StarHorseItem.vue` 把 time/time-picker 统一改为 "datetime" 路由到 `datetime-item`，时间组件全部显示为年月日
- **修复**:
  1. `system.ts` 新增 `dateCompType` 数组（不含 time/time-picker/timerange），`dateCompList()` 改为返回 `dateCompType`
  2. `time-picker-item.vue` 去掉 `normalizeDateModel` 调用，改为专用的 `normalizeTimePickerValue` / `normalizeTimePickerSingle`，直接从 ISO 字符串提取 UTC 时间部分，不经过日期格式化
- **关键架构**: `dateType` 用于 date_utils.ts 的类型判断（全量），`dateCompType` 用于 StarHorseItem 组件路由（仅日期选择器类型）

## 修复时间类型不兼容带时区偏移的日期时间字符串

- **文件**: `src/api/date_utils.ts`、`time-picker-item.vue`、`time-item.vue`
- **问题**: 后端返回 `"1970-01-01 08:11:01+08"` 格式的值时，`formatTimeValue` 和 `normalizeTimePickerSingle` 都无法识别，直接原样返回了完整日期时间字符串
- **修复**:
  1. `date_utils.ts` 新增 `extractTimePart` 工具函数，统一从各种时间格式中提取时间部分：纯时间字符串、带时区偏移的日期时间（`1970-01-01 08:11:01+08`）、ISO 字符串
  2. `formatTimeValue` 中数组遍历时对每个元素调用 `extractTimePart` 提取时间
  3. `time-picker-item.vue` 的 `normalizeTimePickerSingle` 新增带时区偏移格式的正则匹配
  4. `time-item.vue` 的 `normalizeTimeSelectValue` 新增带时区偏移格式的正则匹配

## 修复 datetime-item 对 time 子类型的委托渲染

- **文件**: `datetime-item.vue`、`date_utils.ts`
- **问题**: 字段配置为 `type: "datetime"` + `preps.type: "time-picker"` 时，`StarHorseItem` 路由到 `datetime-item`，但 `el-date-picker` 不支持 `type="time-picker"`，`getDateValueFormat("time-picker")` 也返回 fallback `"YYYY-MM-DD"`，导致时间值被格式化为日期
- **修复**:
  1. `datetime-item.vue` 新增 `isTimePickerSubType` / `isTimeSubType` 判断，对 time 子类型委托渲染 `time-picker-item` / `time-item`，避免双层 `starhorse-form-item` 包裹（设 `bareFlag=true`）
  2. `onBeforeMount` 中对 time 子类型跳过 `normalizeDateModel`，由委托组件自行处理
  3. `getDateValueFormat` / `getDateDisplayFormat` 新增 time/time-picker/timerange 映射
  4. `normalizeSingleValue` 新增 time 类型子类型的 `extractTimePart` 处理

## 重构日期/时间组件的异步数据格式化机制

- **文件**: `datetime-item.vue`、`date-item.vue`、`time-picker-item.vue`、`time-item.vue`
- **问题**: `onBeforeMount` 时后端数据尚未返回，格式化无效；旧方案用 `closeWatch`（一次性 watch + 自动停止），仅处理首次数据到达，后续 formData 变更不再格式化
- **方案**: 将"一次性 watch + onBeforeMount 初始化"替换为"持久化幂等 watch"
  - 去掉 `onBeforeMount` 中的 `initDateValue()` 调用（datetime-item / date-item），由 watch 统一处理
  - watch 不自动停止，`{ immediate: true }` 保证组件挂载时已有数据也能处理
  - 幂等保护：字符串用 `normalized !== val` 比较，数组用逐元素比较，仅值真正变化时才写回 formData，防止无限循环
  - 删除 `initDateValue` 函数（datetime-item / date-item）和 `closeWatch` 变量（四个组件）

StarHorse Lowcode 组件库架构

概述

StarHorse Lowcode 是一套基于 Vue 3 + Element Plus 的低代码组件库，提供表单、表格、对话框、树形控件、数据选择器等核心业务组件，以及丰富的表单项组件，支持配置化驱动的页面开发。

技术栈

  • Vue 3 — Composition API + <script setup>
  • Element Plus — 基础 UI 组件库
  • Pinia — 状态管理
  • TypeScript — 类型系统
  • Vite — 构建工具
  • sortablejs — 拖拽排序
  • vuedraggable-es — Vue 3 拖拽组件

安装与使用

全局注册

ts
import { createApp } from 'vue'
import StarHorseLowcode from 'star-horse-lowcode'

const app = createApp(App)

app.use(StarHorseLowcode, {

内部机制

本文档说明组件库的核心内部机制，理解这些机制对于正确配置和使用组件至关重要。

1. prepsFilter — 属性透传机制

核心原理

所有表单项组件通过 v-bind="prepsFilter(field.preps)" 将 field.preps 中的属性透传给底层的 Element Plus 组件。这意味着 field.preps 中除了框架内部使用的属性外，其余属性会直接传递给对应的 el-xxx 组件。

vue
<!-- input-item.vue 中 -->
<el-input v-bind="prepsFilter(field.preps)" v-model="normalData" />

<!-- select-item.vue 中 -->
<el-select v-bind="prepsFilter(field.preps)" v-model="formData[field.fieldName]" />

prepsFilter 处理逻辑

prepsFilter 函数会做以下处理：

  1. 移除空值属性：值为 undefined、null、""、NaN 的属性会被删除（只读属性除外）
  2. 字符串布尔值转换："true" → true，"false" → false
  3. 返回处理后的对象，供 v-bind 使用

框架内部使用的 preps 属性（不会透传给 Element Plus）

如何使用 Element Plus 原生属性

由于 v-bind="prepsFilter(field.preps)" 的透传机制，你只需在 field.preps 中添加 Element Plus 组件支持的任何属性即可：

ts
// input-item 支持 el-input 的所有属性
{
  fieldName: 'name',
  type: 'input',
  preps: {
    placeholder: '请输入姓名',     // el-input 的 placeholder
    maxlength: 50,                  // el-input 的 maxlength
    clearable: true,                // el-input 的 clearable
    showWordLimit: true,            // el-input 的 showWordLimit
    size: 'large',                  // el-input 的 size
    validateEvent: true,            // el-input 的 validateEvent
  }
}

// select-item 支持 el-select 的所有属性
{
  fieldName: 'status',
  type: 'select',
  preps: {
    values: [{ name: '启用', value: '1' }],
    placeholder: '请选择状态',     // el-select 的 placeholder
    clearable: true,                // el-select 的 clearable
    multiple: true,                 // el-select 的 multiple
    collapseTags: true,             // el-select 的 collapseTags
    collapseTagsTooltip: true,      // el-select 的 collapseTagsTooltip
    filterable: true,               // el-select 的 filterable
    allowCreate: true,              // el-select 的 allowCreate
    defaultFirstOption: true,       // el-select 的 defaultFirstOption
  }
}

重要提示：框架内部使用的属性（如 values、dataRelation）即使写在 preps 中也不会冲突，因为它们要么被组件内部消费，要么 Element Plus 不识别会自动忽略。

2. FormulaEngine — 公式计算引擎

公式引擎支持在字段值变化时自动计算并回填结果。配置在 field.preps.formula 或 field.formula 中。

typeFormulaType是—公式类型
sourceFieldsstring[]是—依赖字段列表，值变化时触发计算
expressionstring否—公式表达式，使用 ${fieldName} 引用字段值
branchesConditionBranch[]否—条件分支（type=condition）
lookupMappingsLookupMapping[]否—联动回填映射（type=lookup）
precisionnumber否—精度
prefixstring否—前缀（如 '¥'）
suffixstring否—后缀（如 '元'、'%'）
dateUnit'year'|'month'|'day'|'hour'|'minute'|'second'否—日期单位
dateMode'diff'|'offset'|'format'否—日期计算模式
dateOffsetnumber否—日期偏移量

formatArgstring | number否—格式化参数

defaultValueany否—条件不匹配时的默认值

8 种公式类型

1. calc — 数学运算

ts
{
  fieldName: 'totalPrice',
  preps: {
    formula: {
      enable: true,
      type: 'calc',
      sourceFields: ['price', 'quantity'],
      expression: '${price} * ${quantity}',
      precision: 2,
      suffix: '元',
    }
  }
}
// 支持所有 JS 数学运算：+ - * / %，以及 Math 对象方法

2. concat — 字符串拼接

ts
{
  fieldName: 'fullName',
  preps: {
    formula: {
      enable: true,
      type: 'concat',
      sourceFields: ['lastName', 'firstName'],
      expression: '${lastName}${firstName}',
    }
  }
}

3. condition — 多分支条件判断

ts
{
  fieldName: 'level',
  preps: {
    formula: {
      enable: true,
      type: 'condition',
      sourceFields: ['score'],
      branches: [
        { when: '${score} >= 90', then: '优秀' },
        { when: '${score} >= 60', then: '及格' },
      ],
      defaultValue: '不及格',
    }
  }
}

4. lookup — 联动回填

ts
{
  fieldName: 'productCode',
  preps: {
    formula: {
      enable: true,
      type: 'lookup',
      sourceFields: ['productCode'],
      lookupMappings: [
        { key: 'P001', values: { productName: '商品A', price: 99.9 } },
        { key: 'P002', values: { productName: '商品B', price: 199.9 } },
      ],
    }
  }
}

5. aggregate — 聚合运算

ts
{
  fieldName: 'totalAmount',
  preps: {
    formula: {
      enable: true,
      type: 'aggregate',
      sourceFields: ['items'],
      aggregateField: 'amount',
      expression: 'sum',
      precision: 2,
    }
  }
}

6. dateCalc — 日期计算

ts
// diff 模式

规则引擎

组件库内置前端本地执行的规则引擎：规则以可视化流程（flowContent JSON）形式从后端拉取并缓存到浏览器内存，字段变更 / 按钮点击时本地零网络开销执行，实现对表单字段的显隐、必填、禁用、赋值、选项覆盖等控制。

核心设计原则：

  • 核心库无状态：所有后端交互通过 configureRuleEngine 从外部注入，核心库不感知接口地址与 HTTP 实现
  • 一次拉取，本地执行：规则仅在 ON_LOAD 时拉取一次并缓存；ON_CHANGE / ON_BUTTON_CLICK 直接读缓存执行，零网络开销
  • 与联动策略独立：联动是声明式配置，规则引擎是流程编排，二者各行其是、可叠加使用

快速接入

第一步：注入配置

ts
import { configureRuleEngine } from "star-horse-lowcode";

configureRuleEngine({
  // 规则拉取处理器：接收 formId，返回 { triggerEvent → flowContent[] }
  fetchRulesHandler: async (formId) => {
    const res = await postRequest(`/userdb/ruleEngine/fetchRules/${formId}`, {});
    return res?.data?.data ?? {};
  },
  // http-call 节点的 HTTP 执行器
  httpCallHandler: async (url, method, body) => {
    const res = method.toUpperCase() === "GET"
      ? await getRequest(url, { params: body })
      : await postRequest(url, body);
    return res?.data?.data ?? res?.data;
  },
});

拉取与缓存机制

  • 并发保护：同 formId 的并发拉取合并为同一个 Promise，不会重复请求
  • 失败降级：拉取失败时缓存空对象，不阻塞表单渲染；未注入 fetchRulesHandler 时引擎静默不工作
  • 手动清除：clearRuleCache(formId?) 清除指定/全部缓存（含防抖定时器与选项覆盖）
  • 多用户并发：缓存位于各浏览器会话内存中，天然按用户隔离；后端只需保证接口幂等，规则更新后重新打开表单即加载最新版本

选项覆盖（optionsOverride）

6 个选项类组件（select / radio / checkbox / tselect / transfer / cascade）的选项 computed 统一接入覆盖机制：

ts
// 组件内部（以 select-item 为例）
const selectOptions = computed(() => {
  const ruleFormId = props.field.preps?.ruleEngineConfig?.formId || props.field.preps?.formId;
  if (ruleFormId) {
    const override = getOptionsOverride(ruleFormId, props.field.fieldName);
    if (override) return override;   // 规则下发的选项优先生效
  }
  return props.field.preps?.values || [];   // 静态兜底
});

规则流设置选项时：

  1. 写入响应式存储 optionsOverrideStore（reactive Map，key 为 ${formId}:${fieldName}）→ 组件 computed 自动重算，无需 triggerRef
  2. 同时按组件类型落到对应 preps 属性：values（select/radio/checkbox 等）/ data（tselect/transfer）/ options（cascade）
  3. 读取入口 getOptionsOverride(formId, fieldName)，返回 undefined 表示无覆盖
